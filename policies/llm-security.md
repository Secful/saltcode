# LLM Security Policies

Salt Code enforces security guidelines for code that integrates with or is generated by large language models.

## Categories

- **Indirect Prompt Injection** — External data sources that manipulate LLM behavior
- **Insecure Output Handling** — Unsanitized LLM output used in system calls, SQL, or HTML
- **Training Data Poisoning Vectors** — Code patterns that could introduce poisoned data
- **Model Denial of Service** — Patterns that cause excessive LLM resource consumption
- **Supply Chain Risks** — Insecure AI-generated dependency suggestions
- **Sensitive Information Disclosure** — LLM prompts or context containing credentials or PII
- **Insecure Plugin Design** — LLM plugins without proper input/output validation

## Examples Salt Code flags

- User-controlled input passed directly into LLM prompts
- LLM output rendered in HTML without sanitization
- Credentials or API keys included in prompt context
